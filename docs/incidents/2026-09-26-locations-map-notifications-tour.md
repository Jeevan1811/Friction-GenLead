# Incident: Locations actions, map empty state, and decorative notification bell

- **Surface / symptoms:** On the production Locations screen, grid cards and table rows looked actionable but did nothing. The status filters did filter the table and map together, but an empty filtered result displayed copy suggesting the entire dataset had no coordinates. The header bell was a noninteractive icon with a permanently displayed dot.
- **Impact:** Users could not open a company from a location, the map empty message misdiagnosed a zero-match filter as a dataset-wide coordinate gap, and the notification affordance had no function. This was not a failure of filter-to-map wiring: read-only production QA showed `Verified` had zero saved locations, `Unverified` returned locations, and `Mine` narrowed list and map together.
- **Recovery in source:** Use linked location cards and keyboard-accessible company links in table rows; display filtered and mapped result counts; support clearing filters; defer text search and preserve prior row-array identity when 30-second Sheet refreshes return unchanged data. Use Canvas for Leaflet paths and non-permanent cluster labels. Map copy now distinguishes zero filter matches, matching rows without coordinates, and mapped rows. The header bell lazily loads saved follow-ups due/overdue in the next seven days with retry/empty states and links to company details or the full Follow-ups page. It does not send push or email notifications.
- **Guide coverage:** Expand the replayable Settings walkthrough across Search, the reminder bell, Companies, Locations, Contacts, Original data, Follow-ups, Searches, the live Google Sheet shortcut, Rejected and Settings. Keep its initial step on `/search`, since `/` redirects to Search and caused earlier route flicker. Assistant help uses matching descriptions.
- **Prevention/tests:** `apps/web/tests/locations-interactions.test.mjs` covers linked controls, map/filter counts, Canvas map labels and reminders. `apps/web/tests/dashboard-tour-routing.test.mjs` covers actual tour targets/routes and the Sheet/bell steps.
- **Verification:** Frontend Node suite **17 passed**, web TypeScript passed, research backend **158 passed**, optimized Next builds passed locally/on VPS. PR #18 merged as production commit `b6e906f`; only the GenLead web process restarted, API health remained `ok`, and both named PM2 processes were online. Authenticated live QA passed: 6,329/6,360 locations mapped; Verified zero-result and Clear behavior correct; Mine 26/26 mapped; grid-card and table-link navigation both opened company drawers; reminders loaded; full 11-step tour finished at Settings and remained replayable.
- **Performance/observability limit:** Search is deferred and map paths use Canvas/grouped coordinates, but no controlled before/after latency benchmark or browser DevTools console audit was captured. The DevTools MCP session had only `about:blank`, not the authenticated in-app-browser tab; no credentials were entered into another browser. Refresh remains 30-second/focus polling rather than push.
- **Safety:** No Sheet rows, saved records, SMTP/auth settings, secrets, or other VPS services were changed. Existing production filters were only read during QA.
