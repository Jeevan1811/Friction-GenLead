# Map cards and dashboard overlays

- Symptom: map names wrapped into an unreadable narrow column under a source badge. Long account labels and help panels could extend beyond small viewports; a nested confirmation could close its parent drawer.
- Evidence: local DOM measurement showed title/address width below 1px. Synthetic Playwright reproduced small-viewport panel placement and nested Escape problems. Fixes-only QA then reproduced an open card disappearing during desktop/mobile resize; source inspection showed separate responsive layout trees remounted the page. Render inspection found drawer actions behind mobile navigation/chat.
- Root causes: a minmax/auto popup grid let the badge take the available width; popovers used guessed heights; responsive layout replaced the page subtree; page animation stacking contexts trapped modal z-order.
- Repair: separate readable popup rows, map-aware dimensions, scroll and 44px close target; exact-company links; measured/flipped anchored panels; stable responsive page subtree; modal portals and nested keyboard ownership. Map zoom cluster rebuild retains the selected location. Delayed tile errors remain visible while popup controls are active.
- Verification: synthetic responsive/keyboard/link/error/resize checks and rendered desktop/phone screenshots. Final staged-build/runtime gate and production smoke recorded in WORKLOG. No production data is used in these fixtures.
- Release boundary: original design retained. Larger all-company cluster browser, missing company-name investigation, new light-theme design and time-savings/usage enhancements are separate pending work. The current cluster preview still limits popup entries to eight with an explicit remainder; it does not yet expose every company in a large cluster.
- Rollback: preserve previous production revision and `.next` directory before swapping a completed staged build. Restart only GenLead web after a validated swap. Do not reset/stash/delete user files, credentials, ecosystem config or research virtualenv; no Sheet rollback is needed because this release writes no data.
